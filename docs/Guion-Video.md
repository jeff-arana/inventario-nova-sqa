# Recorrido visual del desarrollo y sus controles

El recorrido está pensado para una grabación de escritorio de 4 minutos y 45 segundos. El contenido puede mostrarse sin narración mediante cambios reales entre VS Code, terminal, navegador y archivos de métricas. El objetivo es que cada pantalla tenga una función y no dependa de diapositivas estáticas.

| Tiempo | Pantalla | Acción visual |
|---|---|---|
| 00:00–00:40 | VS Code y aplicación | Abrir Inventario Nova; mostrar estructura y objetivo |
| 00:40–02:30 | Terminal, VS Code y GitHub | Crear rama, cambiar validación, registrar commit, abrir PR y revisar build/test/analyze/report |
| 02:30–03:25 | Panel de calidad | Revisar cobertura, bugs, code smells, duplicación; anotar fuente |
| 03:25–04:05 | Archivo de métricas | Comparar referencia inicial y estado final con tabla y notas |
| 04:05–04:45 | Editor y reportes | Mostrar conclusiones y próximos controles |

Para que una grabación sea plenamente verificable, las pantallas de GitHub o Sonar deben registrarse durante una ejecución real. La alternativa visual usa capturas de referencia claramente identificadas como tales. La grabación no requiere música ni efectos; el tamaño recomendado es 1280 × 720 y el formato final MP4.
